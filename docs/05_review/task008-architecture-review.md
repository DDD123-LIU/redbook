## 架构决策及边界

Edge 适配器只接收代理已绑定的受支持 Tab。采集模块负责私有原始观察、单执行槽、CLI 尝试、材料校验及恢复。SQLite 负责关系、状态约束和事务。浏览器读取、CLI 和文件校验均在数据库事务外执行；材料归账和对应检查点在同一同步事务提交。

初始“不改 schema”计划不能满足损坏修复：同 H 成功唯一与旧引用不可改写，使新文件返回仍指坏路径的 duplicate。C2C ITERATION1 实际建议定向迁移。最终采用 [ADR-002](../04_specs/architecture-decisions/ADR-002-material-repair-records.md)：普通成功仍按内容/H 去重；显式修复追加指向普通成功根的物理记录。`artifact_hash` 表示确定性的文件引用清单，`material_hash` 仍只表示正文、有序媒体等内容身份。

修复不表示源内容改变，也不因物理记录 ID 改变就认定旧分析失效。TASK-009 后续须按同根、同 H 和实际输入复用有效分析；本轮没有提前实现009。来源材料、旧版本和坏文件均保留。完整 URL 只在私有输入中保存。

## 发现及关闭证据

1. **AR008-01 / P1，持久化与发现范围。** 适配器原未等待异步 `recordDiscovery`。现读取后等待保存，成功后才滚动。恢复核对来源范围；读取和滚动失败停止并保存局部状态。独立合成复现已验证异步保存顺序、跨来源拒绝和滚动失败。collection 批次 ID 不写入 delivery 外键。

2. **AR008-02 / P1，坏缓存被历史成功掩盖。** 原 `resume` 只看成功行，坏图仍返回 complete；坏正文再次采集会返回旧坏 duplicate。独立夹具实际复现这两种错误。现发现和恢复重新检查正文、图片及封面文件；坏引用不能作为有效 duplicate 归账。本轮 unknown、blocked 和未处理项保留 pending，不再被历史成功状态抹除。新增 RED/GREEN 及最终24项测试覆盖这些分支。

3. **AR008-03 / P1，不可变修复与迁移。** 修复必须指向同内容、同 H、同媒体类型及完整性的普通成功根，不能串帖或建立修复链。API 和数据库触发器共同约束。原生 SQL 曾可在升级库写入 ordinary 行的非空 artifact_hash，而 fresh 库拒绝；共同触发器已补齐。独立使用完整 v1 schema 建库、升级后插入非法行，fresh 和 migrated 均实际拒绝。普通成功唯一和修复重放幂等分别保留。

4. **AR008-04 / P1，材料与检查点归账。** `saveReceipt` 现将材料、来源状态和检查点放入同一事务。独立追加隔离故障：在检查点 INSERT 处用 SQLite 触发器抛错，材料新增数为0，原 pending 保留，命令退出0。因两项同事务，不存在已提交材料却未提交该检查点的独立提交窗口。另有 receipt 已落盘、归账前异常的恢复测试。相同提交时刻以 rowid 打平，避免取旧检查点丢失待处理或成功引用。

5. **AR008-05 / P1，认证停止及条件恢复。** 原登录失败后仍调用第二来源。现检查 stdout 和 stderr 的明确认证信号；blocked 或 unknown 停止后续来源。显式访问恢复证据保存后，可在同一批次续作；不会永久要求另建批次或手工改库。尝试预算按运行计算，无回执的历史尝试继续保持待核实。相关合成测试已通过；未制造真实账号登录失败。

6. **AR008-06 / P1，执行槽和晚到工作者。** 外部动作前及异步返回后核对 owner/run/generation/stop。缓存校验后的检查点写入也在事务内复核。旧进程存活或未知时拒绝接管，包括当前 PID；没有超时抢槽或 PID override。同一 collector 重复 claim 也拒绝，内部续作用显式 token。晚到结果保留为证据，不推进新工作者。

7. **AR008-07 / P2，仅修复必要材料。** 单图损坏只请求缺失序号；重复修复仍指普通根。仅正文损坏时，独立 attempt 的 settings 关闭 image_download，并复用经验证的有效图片；不会省略 --index 后悄悄重下全部图片。夹具按此真实设置不产新图，校验新修复行及旧行/坏文件保留。源 settings 只读，修改限于新副本。
