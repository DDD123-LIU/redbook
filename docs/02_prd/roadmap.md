## 阶段顺序
1. RDD 基线：已确认并提交 def36b5。
2. PRD v0.1：用户已确认范围和验收，含 F08 双门槛及系统稳定性修订；独立本地 Git 留存。

4. 首期实现：按已确认任务和 Spec 分步开发、本地验证，按完成的任务提交 Git。
5. 实际品味试验：每批 3 条，总量试用时决定；关注/探索从开始测试分别累计至少 95%，用户明确确认正式推送。
6. 正式运行：每日及指令推荐、版本化指标、定期 review；两次策略调整内恢复到 95%，失败明确判定。
7. 小红书模式成立后：再评估推特，不提前扩范围。

## 两种版本
产品版本用于发布功能范围；推荐策略版本用于追踪偏好和筛选变化。
“最多两个调整版本恢复”拟对应推荐策略版本，与软件发布次数分开。新版效果只算由新规则实际产生的推荐，历史累计仍保留。
具体版本切换、样本量和样本充分性写入 Spec 和试验约定，不给旧结果贴新标签。

## 失败与推进
接入验证失败先报告阻塞，再决定替代生态路线或范围调整；不能默认付费 API。
质量未通过不宣称模式成立，最多两版恢复失败须 review 原因和下一步，不能无限声称正在优化。
不自动创建定时任务、登录账号或发送真实消息；本路线只是阶段规划。
没有用户约定的交付日期，不虚构日期承诺。
