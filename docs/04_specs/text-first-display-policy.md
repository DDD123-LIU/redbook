# 正文优先推送规则（跨任务生效）

日期：2026-10-29。执行者：Codex。来源：用户明确“优先发送推送，哪怕图片被拦截，也要发正文”，并要求TASK016以外Markdown同步修订。Gate3：需求明确。本规则覆盖TASK003/011/012/013/015/016中的旧展示失败规则，不追溯改写历史实测结果。

已通过当前适用筛选、正文及来源可验证的帖子，优先发送完整正文。图片超出已验证图文组合、缺失/损坏/不可解码、获取或上传失败、上传结果unknown时，不再仅因图片问题阻断正文；发送标题、作者、完整正文、原文入口和明确的“图片未附”说明及原因。该payload的完整是指实际发送正文完整，不表示原帖图片齐全或已分析。

不静默省图、不改摘要、不截断正文，不通过降级假造图片上传成功。unknown图片保留原intent/receipt，不重传；正文发送仍用原delivery幂等/回执/unknown核实契约。已成功发送的帖子不为补图片再次推送。能完整展示图片且处于已验组合时仍带原图，不因为正文优先一律取消图片。

正文缺失、正文hash或来源错绑、筛选资格不成立、正文单独仍超出当前支持容量、整体发送结果未知、用户停止/低额度/登录安全限制等不是图片降级理由，仍按原契约保存和停止。图片采集/分析的complete/partial/unknown定义不变，TASK007/008/009/010不能因允许发正文而冒称图片材料完整或模型读过图。

实现：createDisplay默认allowTextFallback=true，沿既有formatMessage再构建完整正文payload，输出media_fallback.kind=text_only及原始reasons，并在正文后显示原因。严格媒体模式仅用于底层媒体恢复契约测试或显式专门调用，正式推送入口不得用它恢复“图片挡正文”。图片获取阶段失败也须登记partial材料并进入正文展示，不在上游整篇丢弃。纯formatMessage仍描述给定材料能否完整图文组合，buildBatch负责已授权降级决策。
