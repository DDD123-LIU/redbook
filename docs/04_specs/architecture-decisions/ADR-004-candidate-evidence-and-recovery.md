# ADR-004：首页候选来源、比较证据及恢复边界

日期：2026-10-23。执行者：Codex。状态：已接受，Architecture Review及本卡交付范围通过；实际提交见Git。

## 背景
TASK-010须复用008/009而不把首页内容变成收藏。008的收藏resume不能定向恢复无收藏观察的候选。009执行器原仅支持逐帖分析与偏好汇总。现有v3候选、决定和检查点足以保存业务关联。

## 决定
保留v3及Node标准库。首页模块只写content/candidate/batch及来源检查点，预算以DB唯一候选计数。候选模块串行交接008/009的共享槽，单候选分阶段落盘。成功采集receipt以确切attempt核实并复用原归账，不走全库resume；未知不盲重试。

筛选使用009同一官方订阅CLI，执行器增加可选schema/prompt/payload，默认分析与偏好输入保持原义。比较结果必须有候选/基线证据定位、具体差异和覆盖说明；代码核对引用和版本后才生成不可变decision。语义判断仍有模型能力限制，不能证明用户认可。

## 权衡与回退
不引入新采集协议、偏好系统或任务队列。单机阶段交接要求每次复核状态，不能宣称跨外部调用原子或无在途竞态。过大或不足的比较输入hold并记录，不静默截断。候选状态可更新为当前投影，历史决定和证据保留。回退本任务代码不修改原009私有库，也不撤销外部动作；本卡不外发推荐。

开发前C2C四项P0及Sol精简设计已核对，见task010-plan及Architecture Review。实现/测试/C2C最终接受另行记录。
