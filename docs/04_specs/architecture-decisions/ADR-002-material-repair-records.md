# ADR-002 同内容损坏材料的不可变修复记录

日期：2026-10-21—22。执行者：Codex。范围：TASK-008必要存储修订。状态：采用；C2C ITERATION1设计、Sol最终Architecture Review及C2C ITERATION2 DONE—ACCEPT通过，迁移与实现证据见008。

## 问题及证据

007成功材料以`(content_id,material_hash)`唯一，并禁止覆盖版本。图损坏后，CLI按`--index`只补缺图，恢复后的内容哈希与原版相同，但文件位于新attempt。原API返回仍指向坏文件的duplicate。把路径或时间塞入内容哈希、覆盖旧图、将unknown称成功，均违反本轮要求。旧schema并非支持该分支；本轮已显式提交C2C及Architecture Review，不静默改变007。

## 选择

Schema v2增加显式`repair_of_material_version_id`和独立`artifact_hash`。普通成功材料仍按内容/H去重。只有明确修复输入才能新增同H物理记录；修复指向同内容、同H的普通成功根，不建立修复链。产物指纹由规范化正文/有序图/封面的路径及字节hash确定。相同修复产物重放幂等。父记录、坏图、旧分析及历史均保留。

`material_hash`仍表示内容字节身份，不混入路径/时间。`material_version_id`明确区分物理材料记录。修复记录不表示源内容改变。TASK-009后续必须按同根/同H及实际分析输入校验复用，不因修复物理ID变化自动重跑分析；本轮不实现009。

008只在CLI业务/源DB关联、完整正文、全部有序图片hash与解码验证通过后保存成功修复记录。归账和检查点同SQLite事务；无效duplicate不能推进成功。有效旧图片复用，现有CLI只下载缺失序号；若来源媒体或正文已变，停止合并不同版本并明确报告，再按确证刷新处理，不用旧图凑完整。

## 迁移和回退

不在openStore中自动接管v1或外部下载器库。显式`upgradeStoreV1(source,destination,{backupPath})`保留停止写入的v1源，先做一致备份，隔离新目标执行迁移。所有目标必须新路径；失败不覆盖源或旧备份。验证外键、完整性、版本、原内容/关系、普通去重、repair约束及事务回滚。v2备份/新路径恢复及007完整回归必须通过。实际调用及最终API以storage-contract修订为准。

回退使用原v1源或新路径恢复备份；不能把活动v2库直接当v1打开。迁移不撤回平台动作，不重下素材，不推送或部署。

## 权衡与未验证

增加两字段和受约束索引/API，避免新增独立文件管理系统、私有引用协议或通用版本框架。必须付出迁移/回归成本，不能借008绕过Review。真实坏图补采将用隔离合成材料和现有CLI参数契约测试，不能为验收破坏本轮真实成功图片。
