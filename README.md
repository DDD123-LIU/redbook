# Redbook · 小红书个性化推荐助手

从小红书推荐流读取内容，结合偏好与反馈筛选，通过飞书发送推荐并核实送达，形成“发现 → 阅读 → 筛选 → 展示 → 投递 → 反馈”的本地闭环。

本仓库发布核心源码、运行脚本、测试与脱敏项目文档。真实账号、浏览器登录态、私有偏好材料和运行数据库不随仓库分发。当前版本为需要本机接线的项目源码，并非下载即用的托管服务。

## 背景与解决的问题

推荐流信息量大，逐条阅读和判断成本高。Redbook 将原文阅读、偏好筛选、成功来源去重和投递回读串联起来，并区分内容耗尽、平台访问障碍、额度暂停和未知发送回执，避免把执行故障当成推荐完成。

## 核心功能

- **推荐入口**：每日自动推荐 10 条；本人绑定飞书会话发送“再来3条”时，有限单轮追加最多 3 条。独立主动 10/20 条入口已撤销，探索入口不支持。
- **正文优先**：读取原文正文，筛选时使用偏好基线和最新反馈；图片未经过模型分析时明确说明。
- **连续补量**：每日批次不足 10 条时继续采集与筛选，只发送剩余需要的数量；达到目标并完成末轮回读后停止。
- **投递核实**：保存推荐身份与发送回执，精确回读；所有入口共用成功来源去重，未知回执保留待核实。
- **反馈与偏好**：记录反馈、查询与修订，支持后续筛选使用。
- **状态与恢复**：SQLite 持久化批次、执行槽、材料、投递和反馈；按证据恢复，保留历史状态。
- **有限停止与重试**：当日额度暂停、平台屏障停止、连续 5 篇详情执行异常停止，以及进度文件占用的有限重试。

## 业务流程

```text
每日计划 / 本人“再来3条”
          ↓
核实额度、执行互斥、当日批次
          ↓
发现来源 → 阅读正文 → 偏好与反馈筛选
                         ↓
                    生成展示材料
                         ↓
                  飞书发送 → 精确回读
                         ↓
             保存成功来源、回执与反馈
                         ↓
         日批不足则继续；达标或真实阻塞则停止
```

日批计划时间为 UTC+8 的 11:15，最迟 11:30（含）实际启动达标。迟到仍只处理当天，并如实记录时间验收失败；跨日不追旧日欠额。

## 技术栈

| 层次 | 实现 |
| --- | --- |
| 运行时 | Node.js ESM，`node:sqlite`、标准库 |
| 状态存储 | SQLite，`src/schema.sql` |
| 采集 | Ego Browser Lite、本机已登录浏览器 |
| 模型筛选 | 本机 Codex 运行环境与既有筛选契约 |
| 飞书 | 官方 `@larksuiteoapi/node-sdk`，Axios |
| 验证 | Node 内置测试运行器，本地合成夹具 |

## 环境要求与依赖

- 本次公开副本使用 Windows、Node.js **24.19.0** 验证；依赖内置 `node:sqlite`。其他系统与 Node 版本未在本轮验证。
- 核心模块主要使用标准库。飞书 SDK 测试和真实投递还需要官方 SDK 与 Axios。
- 真实采集需要已安装的 Ego Browser Lite；真实筛选需要本机 Codex 环境；登录和验证码由账号本人处理。
- 图片处理需要原有图片解码/转换工具；具体依赖与限制见源码及运行配置说明。

## 配置与运行

### 1. 获取源码与安装可选集成依赖

```powershell
git clone https://github.com/DDD123-LIU/redbook.git
cd redbook
node --version
npm install --no-save --package-lock=false @larksuiteoapi/node-sdk axios
```

仓库没有 npm 构建步骤或 Web 前端。安装命令仅为本地 SDK 集成验证准备依赖，不会发送消息。

### 2. 运行本地测试

```powershell
node --test tests/*.test.mjs
```

测试使用临时目录和合成材料。个别测试会在 `.codex/` 写入结果，日志和运行产物应保持在本地。最新实际执行结果见[公开版验证记录](docs/06_delivery/public-release-verification.md)。

### 3. 准备真实接线

参阅[公开版配置说明](docs/06_delivery/public-setup.md)和[脱敏宿主配置](examples/host-config.example.json)。配置示例中的路径和标识必须替换为本机值；示例保持 `productionEnabled: false`。

`src/orchestration-host.mjs` 导出 `runTask013Host()`，供已有宿主注入运行时使用，直接 `node src/orchestration-host.mjs` 不会启动推荐。`.codex/task016-auto-worker.mjs` 导出当前日批与追加执行函数，但真实调用依赖正式本地数据库、偏好材料、浏览器会话及飞书绑定文件，不能仅复制一个 JSON 就运行。

本仓库不创建新的每日计划，也不随发布执行真实采集、模型调用或飞书投递。正式接线应先在隔离环境核实所有依赖、绑定与回执契约，再启用原有宿主计划。

## 已知限制

- 真实运行依赖本机私有基线、账号绑定、工具安装和登录态，尚未提供通用一键初始化。
- 保留原有目录与运行脚本，部分脚本仍带有本机路径约定；公开副本已将 Windows 用户名替换为 `YOUR_USER`，需要部署者逐项配置。
- 文档含多个历史阶段；当前入口与数量以[统一规则](docs/04_specs/recommendation-count-policy.md)为准，历史 20 条批次与实测不代表当前目标。
- 最终版本自然定时全链路、退出/休眠/离线恢复与长期稳定仍须按各自验收边界验证。
- 本仓库未指定开源许可证；公开访问与 Star 不等于授予任意使用和再分发许可。
